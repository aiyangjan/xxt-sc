# 校享团校园供应链平台 V2 · PRD 要点

> 原文：产品需求与开发 PRD v1.0（2026-09-28）
> 对外产品名：校享团校园供应链平台 V2
> 工程代号：`xxt-campus-platform`
> 本文件为原文的结构化提炼，用于研发执行时快速对照；细节以原文为准。

---

## 1. 一句话定位

「学生消费 + 楼长经营 + 平台运营/财务 + 供应链自助 + ERP/支付协同」的校园供应链平台，**不是单一商城**。

一期必须先跑通一条可核对的资金闭环：

```
学生登录 → 浏览学校/店铺/SKU → 下单并支付 → 楼长接单发货
→ 学生确认收货 → 清分/入账 → 财务查询导出 → 部分退款时冲正原流水
```

## 2. 三条交易链（必须分开核算）

| 链 | 内容 |
|---|---|
| 1 | 供应商供货 → 平台采购与入库 |
| 2 | 平台供货 → 楼长采购、调拨与库存 |
| 3 | 楼长销售 → 学生订单、收款、售后和分润 |

## 3. 角色与权限五层（缺一不可）

角色：学生 / 楼长 / 平台超管 / 运营 / 财务 / 供应链供应商 / 校园区域代理 / 仓库 / 审计客服 /（未来骑手）

权限必须同时覆盖：

1. **菜单权限** — 能否看到模块
2. **按钮权限** — 审核、退款、导出、重试、作废
3. **字段权限** — 金额、成本、手机号、身份证、银行卡
4. **数据范围** — 全平台 / 组织 / 学校 / 楼栋 / 店铺 / 供应商 / 本人创建
5. **导出权限** — 字段、时间范围、次数、脱敏、水印

高风险操作：二次确认 + 操作原因 + 审计记录。

## 4. 核心业务红线

### 4.1 价格与库存
- 客户端下单**只提交 SKU 和数量**；应付金额、优惠分摊、手续费、利润、分润**全部服务端计算并保存快照**
- 楼长**不能**改平台统一学生售价；楼栋差异价必须由平台配置价格模板
- 库存扣减与订单创建保持一致；取消/超时/退款/退货按规则释放或回补
- 库存不足、SKU 下架、价格过期、活动库存耗尽 → **不能创建可支付订单**
- 同一 SKU 不能同时存在两个生效的学生售价版本；变价必须生成价格历史，且不影响已支付订单快照

### 4.2 订单与支付
- 订单、支付、履约、售后、清分、ERP 同步**各自独立状态**，不得合并成一个字段
- 支付成功以**渠道回调或后端查单**为准，页面提示不改变事实
- 回调必须校验签名、商户、金额、订单号、幂等键；重复通知不得重复入账
- 已支付订单必须**退款后才允许关闭**

### 4.3 部分退款与售后
- 可退数量 = 已支付数量 − 已退款数量 − 退款处理中数量
- 可退金额 ≤ 该订单行已支付金额 − 已退款 − 处理中；优惠分摊按订单行快照**反向计算**
- 一笔订单可多次部分退款，但总和不得超上限
- **渠道退款成功后**才标记成功并生成冲正账；失败/处理中/人工处理保留原记录
- 清分前退款走原支付链路；**清分后退款生成冲正记录，不删除原流水**
- 售后审核、渠道退款、库存回补、账务冲正**分别审计**

### 4.4 楼长入驻与汇付
- 申请、平台审核、实名认证、汇付个人用户开户、用户入驻、结算配置、银行卡绑定是**不同状态**
- 楼长走**汇付个人用户**流程，不得当作平台商户进件
- OCR 结果仅用于回填建议，**必须用户确认**；敏感字段入库前脱敏或加密
- 汇付订单号、商户原订单号、交易流水号、清分流水号、退款流水号**分别记录，不得合并**

### 4.5 财务与利润
- 销售明细按**订单商品行**输出，区分：交易发生/创建时间、支付/入账完成时间、发货时间、确认收货/完成时间
- 「按交易发生时间」与「按入账完成时间」**不能共用同一筛选语义**
- 销售额/退款额以**分**为单位；报表金额以订单行实付、成本、优惠、手续费、退款、清分流水为依据，**不直接用前端汇总**
- 导出必须与当前筛选条件、数据权限、字段权限、脱敏规则一致；大数据量走异步任务 + 水印

### 4.6 供应链数据隔离（安全红线）
- `supplierId` 从**登录身份和绑定关系推导**，**绝不信任请求参数**
- 混合供应商订单中，不得泄露其他供应商的商品和成本
- 供应商停用/禁用/解绑后，**立即阻断**查询、详情、导出和 API
- 管理员临时扩大数据范围必须设有效期、理由、审计

## 5. 状态机要求

每个对象保存：状态 + 状态时间 + 失败原因 + 操作来源。状态迁移校验前置状态，重复通知不产生重复业务结果。

涉及对象：订单、支付、履约、退款、清分、ERP 同步、楼长入驻。

## 6. API 约定

- 统一前缀 `/api/v1/...`，统一响应结构；一期接口保留兼容适配期
- 领域划分：`/ma/`（学生端）、`/leader/`（楼长）、`/admin/`（后台）、`/supplier/`（供应链）、`/webhooks/`（回调）、`/exports/`（导出）
- 所有写操作支持**幂等键**
- 错误响应：业务错误码 + 可读消息 + 追踪标识 + 是否可重试
- **金额用分，时间用 Asia/Shanghai**，响应不返回未授权敏感字段

## 7. 第三方集成

| 集成 | 要点 |
|---|---|
| 汇付 | 个人开户、用户入驻、绑卡、支付/退款/清分/提现/对账；回调验签、查单、幂等、重试、人工差异 |
| OCR | 百度或阿里云，可切换；识别结果仅回填建议，用户确认后提交；原图与结果有权限和保留期限 |
| 管家婆 ERP | 基础资料同步、采购/入库/销售出库/退货/库存、事件投递；外部单号映射、幂等键、重试、失败队列、人工重放 |

**判定标准**：ERP 同步成功 = 外部系统返回可保存业务单号或明确成功回执；**仅前端提示成功不算成功**。

## 8. 关键验收标准

| 编号 | 场景 | 期望 |
|---|---|---|
| AC-001 | 提交 SKU 和数量 | 服务端按当前价格创建订单，返回价格快照 |
| AC-002 | 支付回调重复到达两次 | 只一次入账，第二次返回幂等结果 |
| AC-003 | 楼长发货 | 状态更新并产生履约事件；其他楼长不能操作 |
| AC-005 | 已付 5 件已退 1 件，申请退 2 件 | 成功；再次超额申请被拒 |
| AC-101 | 供应商 A 查销售明细 | 只返回含 SKU-A 的订单行 |
| AC-102 | 供应商 A 传 supplierId=B | 服务端忽略伪造参数，按绑定范围返回 |
| AC-103 | 财务子账号无成本字段权限 | 成本不显示、不返回、不进文件 |
| AC-201 | 按入账时间导出 | 含清分状态、手续费、汇付流水号、原订单号 |
| AC-202 | 汇付回调金额不一致 | 拒绝入账，记录差异，进人工处理 |
| AC-204 | ERP 投递超时 | 同一幂等键重试，不产生重复单 |
| AC-301 | 新人券配置 15 天 | 有效期按配置，**不得写死 7 天** |

## 10. Definition of Done

需求完成需**同时**满足：

1. 产品规则和验收标准已评审
2. 页面覆盖正常/空/加载/错误/无权限/重复提交六态
3. 后端完成权限、数据范围、幂等、审计、错误处理
4. 订单/资金相关有领域测试 + 接口测试 + 至少一条端到端用例
5. 财务字段与样表核对一致，导出与屏幕筛选一致
6. 第三方有请求、回执、失败、重试、对账证据
7. 文档、接口、配置项、运维告警、回滚说明同步更新

**一个功能必须同时挂：产品需求编号、接口、权限、页面、数据表/对象、日志、测试用例、上线开关。只画页面或只写接口不算完成。**
