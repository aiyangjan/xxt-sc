# 技术规范补充

> 本文填补 PRD 未细化、但研发必须统一的约定。业务规则仍以 `docs/PRD.md` 为准。
> 凡本文与 PRD 冲突，以 PRD 为准；本文未覆盖的部分，实现前先补充本文。

## 1. 统一响应

所有 `/api/v1/**` 接口返回统一结构：

```json
{
  "code": "0",
  "message": "成功",
  "traceId": "a1b2c3d4e5f6g7h8",
  "retryable": false,
  "timestamp": 1769600000000,
  "data": { }
}
```

约定：

- `code = "0"` 表示成功，其余为业务错误码（字符串，便于前端按位分类）。
- **业务异常 HTTP 状态码为 200**，前端依据 `code` 判断，不要依赖 HTTP 状态。
- 只有真正未预期的系统错误才使用 5xx。
- `traceId` 每次响应必带；客服反馈问题时以此定位。
- `retryable = true` 仅用于可安全重试的场景，调用方据此决定是否重试。

## 2. 错误码

编号规则：`{HTTP语义}{领域}{序号}`，共 5 位。

| 段位 | 含义 |
|---|---|
| 前 3 位 | 语义类别（400 参数、401 认证、403 权限、409 业务冲突、504 第三方、500 系统） |
| 后 2 位 | 同类别内序号 |

已定义（见 `ErrorCode`）：

| code | 含义 | 可重试 |
|---|---|---|
| 0 | 成功 | 否 |
| 40000 | 参数错误 | 否 |
| 40100 | 未登录或会话失效 | 否 |
| 40300 | 无权限执行操作 | 否 |
| 40301 | 无权限查看字段 | 否 |
| 40302 | 超出供应商数据范围 | 否 |
| 40901 | SKU 已下架 | 否 |
| 40902 | 库存不足 | 否 |
| 40903 | 价格已过期 | 否 |
| 40904 | 订单不可支付 | 否 |
| 40905 | 退款超出可退上限 | 否 |
| 40906 | 重复退款 | 否 |
| 40907 | 幂等键冲突 | 否 |
| 50400 | 第三方调用超时 | **是** |
| 50401 | 第三方暂不可用 | **是** |
| 50402 | ERP 同步未确认 | **是** |
| 50000 | 系统内部错误 | **是** |

新增错误码必须同步更新本表与 `ErrorCode`，并说明是否可重试。

## 3. 金额

- 存储与传输单位：**分**，类型 `long`。
- 录入/展示转换走 `Amount.yuanToFen(String)` / `Amount.fenToYuan(long)`，**禁止**用 `double` 中转。
- 优惠、手续费、分润分摊使用 `Amount.allocate(totalFen, weights)`：
  - 余数归入最后一行，保证**各行之和恒等于总额**。
  - 权重不得为负、不得全为零；溢出快速失败。
- 数据库字段建议 `BIGINT`，列名以 `Fen` 或 `_fen` 结尾（如 `pay_amount_fen`）。

## 4. 时间

- 时区固定 **Asia/Shanghai**（`application.yml` 已配置 Jackson 与 MVC）。
- 序列化格式 `yyyy-MM-dd HH:mm:ss`。
- 数据库建议 `DATETIME`（本地业务时间）或 `BIGINT`（Unix 毫秒），同一模块内不得混用。
- PRD 要求区分的四个时间必须分别落字段，不得复用：
  交易发生/创建时间、支付/入账完成时间、发货时间、确认收货/完成时间。

## 5. 幂等

- 写接口必须支持幂等键，约定请求头：`X-Idempotency-Key`。
- 格式建议：`{业务域}:{业务标识}:{客户端生成UUID}`，例如 `order:CREATE:9f2c...`。
- 幂等键冲突时返回 `40907`，**不重复执行业务**。
- 支付/退款回调的幂等键以渠道侧唯一号为准（商户原订单号 + 交易流水号），不依赖客户端传值。
- 幂等记录需保留：键、请求摘要、结果、时间。（存储方式待 ORM 选型后确定）

## 6. 分页

统一请求参数：`page`（从 1 开始）、`size`（默认 20，最大 200）、`sort`（如 `createdAt,desc`）。

统一返回结构（建议）：

```json
{ "content": [], "page": 1, "size": 20, "total": 1234, "totalPages": 62 }
```

- 导出类接口不走分页，走异步导出任务（PRD 5.10）。
- 禁止无界列表查询；所有列表必须带上限。

## 7. 状态机

每个对象独立状态字段，且配套记录：状态时间、失败原因、操作来源。

| 对象 | 状态字段（建议名） |
|---|---|
| 订单 | `order_status` |
| 支付 | `pay_status` |
| 履约 | `fulfill_status` |
| 退款 | `refund_status` |
| 清分 | `settle_status` |
| ERP 同步 | `erp_sync_status` |
| 楼长入驻 | `onboard_status` |

迁移必须校验前置状态；重复通知不得产生重复业务结果。

> 各状态的**具体枚举值与迁移条件表**尚未定义，属于待补充项（见第 11 节）。

## 8. 供应商数据隔离

- 查询入口统一先取 `SupplierIdentityProvider.currentSupplierId()`。
- 读场景（查询/详情/导出/报表）：使用 `SupplierScope.resolve(requested, current)` —— **忽略请求传入值**，始终用登录绑定值。
- 写场景（结算、提现、配置变更）：使用 `SupplierScope.assertInScope(...)` —— 不一致直接抛 `40302`。
- 混合供应商订单：只返回本供应商的订单行，**不得泄露其他商品与成本**。
- 供应商停用/解绑后，查询入口立即阻断。

## 9. 日志与追踪

- 每个请求生成 `traceId`，写入 MDC 并通过响应头 `X-Trace-Id` 返回。
- 外部传入的 `X-Trace-Id` 必须经 `TraceId.sanitize()` 清洗，不符合字符集则重新生成。
- 日志禁止输出：完整手机号、身份证号、银行卡号、密码、密钥原文。
- 敏感字段展示按 PRD 字段权限脱敏。

## 10. 分层与包结构（暂行，ORM 选型后细化）

```
controller   参数接收、结果封装，不含业务判断
application  用例编排、事务边界
domain       业务规则与不变量（纯逻辑，易测试）
infra        数据访问、第三方适配（汇付 / OCR / ERP）
```

当前工程尚未引入 ORM，`infra` 层待选型后建立。
