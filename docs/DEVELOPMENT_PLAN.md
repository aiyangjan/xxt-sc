# 校享团 xxt-sc 开发计划

## 目标

把当前只有领域规则和规范的 xxt-sc，逐步建设成可运行、可测试、可审计的校享团校园供应链平台。所有开发均通过 GitHub 分支和 Pull Request 完成，main 只接收审核通过的代码。

## 当前基线

- Java 17
- Spring Boot 3.2.5
- Maven
- API 统一前缀 /api/v1
- 金额统一使用分，类型为 long
- 订单、支付、履约、售后、清分、ERP 同步使用独立状态
- 供应商数据范围由登录身份推导

## 分阶段路线

### P0：可运行交易内核（当前阶段）

1. 应用层统一错误响应和 traceId。
2. SKU 价格提供接口，禁止客户端提交价格。
3. 创建订单、查询订单、取消待支付订单。
4. 订单行价格快照、优惠分摊和订单状态迁移接入 API。
5. 退款上限校验接入应用层，先保留支付渠道适配边界。
6. 增加 MockMvc 接口测试和 GitHub Actions JDK 17 测试。

P0 的内存存储只用于建立接口和领域边界，不作为生产数据方案。下一阶段替换为数据库仓储时，API 和领域规则保持不变。

### P1：主数据和持久化

- 用户、角色、学校、校区、楼栋、店铺、供应商。
- 商品、SKU、分类、价格历史、库存和供应商绑定。
- 数据库迁移、分页、幂等记录和审计日志。
- 登录、菜单、按钮、字段、数据范围和导出权限。

### P2：支付、售后和资金

- 微信/汇付支付预下单、回调验签、查单和幂等。
- 部分退款、整单退款、退款回调和清分后冲正。
- 楼长利润、供应商应结、平台收入、手续费和提现。
- 财务销售明细、对账和异步导出。

### P3：楼长和供应链作业

- 楼长入驻、汇付个人用户开户/入驻/绑卡。
- 楼长接单、备货、发货、确认收货、采购、调拨和退货。
- 供应链销售、库存、采购、售后、结算和 API 门户。

### P4：运营与第三方

- 新人券、天天特价、广告、任务和数据大屏。
- 百度/阿里云身份证及银行卡 OCR。
- 管家婆商品、采购、库存、销售、退货和 Outbox 重试。

### P5：切换与未来扩展

- 历史数据映射、灰度、双账核对和回滚。
- 为外卖、骑手、地图和运费模板保留接口，不在当前阶段上线派单。

## 当前 PR 交付范围

本分支只做 P0 的第一条垂直切片：创建订单 → 查询订单 → 取消待支付订单，并把退款上限规则接入应用服务。它不伪装支付、数据库或 ERP 已经接通。

## 每个功能的完成定义

- 有产品需求编号和接口契约。
- 有正常、空、参数错误、无权限和重复提交测试。
- 金额计算使用服务端快照，客户端不传价格。
- 领域规则和状态迁移有单元测试。
- API 有统一错误码和 traceId。
- GitHub Actions 使用 JDK 17 通过。
- 变更通过 Pull Request 审核后才进入主分支。

## 协作规则

- 开发分支：feat/xxx、fix/xxx、docs/xxx、chore/xxx。
- 每个 PR 只解决一个可验收主题。
- 提交信息使用 feat/fix/docs/refactor/test/chore 前缀。
- 代码作者提交，独立审核者审核；不直接改 main。
